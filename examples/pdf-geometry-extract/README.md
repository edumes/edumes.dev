# pdf-geometry-extract

Estudo de caso: [Robôs que operam sistemas sem API, e um painel para comandá-los](https://edumes.dev/casos/orquestracao-rpa/) · Case study: [Robots that drive systems with no API, and a panel to command them](https://edumes.dev/en/cases/rpa-orchestration/)

**PT** · Lê valores de um PDF pelo rótulo impresso e pela posição na página, não pela ordem do texto. Em guias com caixas lado a lado, a extração de texto comum intercala os valores, e "o primeiro número depois do rótulo" sai errado. Aqui o valor que importa é lido em até três lugares independentes, e todos precisam concordar. Se discordarem, o documento é tratado como ilegível: parar e pedir revisão é melhor do que agir em cima do número errado. Dinheiro é sempre `Decimal`.

**EN** · Reads amounts from a PDF by printed label and position on the page, not by text order. On forms with side-by-side boxes, plain text extraction interleaves the values and "the first number after the label" comes out wrong. Here the amount that matters is read from up to three independent places, and they must all agree. If they don't, the document is treated as unreadable: stopping for review beats acting on the wrong number. Money is always `Decimal`.

Todos os documentos são fictícios, gerados pelo próprio teste. / Every document is made up and generated by the check itself.

```bash
uv run check.py
```

- [extract.py](extract.py): `read_amount(path)` and the geometry helpers.
- [check.py](check.py): builds three forms and asserts that text order picks the neighbour box, that geometry gets it right, and that disagreeing readings are refused.
